# SkyShelf · Final 1.0

SkyShelf — защищённое облачное пространство для учебных команд. Сервис объединяет файлы, историю версий, участников, чек‑лист, дедлайн и контролируемую сдачу преподавателю. Проект подготовлен по дисциплине «Создание программного обеспечения», группа ЭФБО-14-24.

## Быстрый запуск на Windows

1. Установите полный **JDK 17 или новее**. Maven, Node.js и Docker для показа готовой сборки не нужны.
2. Полностью распакуйте архив, например в `C:\Projects\SkyShelf`. Не запускайте файлы внутри ZIP.
3. Откройте `start.bat` двойным щелчком.
4. Оставьте два появившихся окна SkyShelf открытыми. Скрипт сам дождётся готовности и откроет `http://localhost:5500`.
5. Для остановки закройте оба окна сервера.

Проверка Java в терминале:

```powershell
java -version
javac -version
```

На macOS/Linux: `bash start.sh`.

## Что реализовано

### Облачное хранилище

- загрузка и точное скачивание TXT, MD, CSV, PDF, PNG, JPG, ZIP, DOCX, XLSX и PPTX;
- папки, поиск, фильтры, переименование, перемещение и избранное;
- корзина, восстановление и окончательное удаление;
- версии файлов с комментарием, автором, контрольной суммой и восстановлением старой версии как новой;
- квоты 15/100/500 ГБ; история версий и корзина учитываются в занятом объёме;
- параллельные загрузки защищены блокировкой пространства.

### Функции для студентов

- отдельные учебные проекты с предметом, преподавателем, дедлайном, описанием, цветом и обложкой;
- роли OWNER, MEMBER и READER;
- чек‑лист сдачи с прогрессом, исполнителями и сроками;
- выбор единственного итогового файла;
- публичная карточка для преподавателя с командой, описанием и проверяемой контрольной суммой;
- экспорт всего проекта в ZIP с манифестом и префиксом `FINAL_` у итогового файла;
- журнал действий команды;
- кастомизация личного интерфейса и каждого проекта.

### Защита данных

- пароли пользователей и пароли публичных ссылок — Argon2id с солью;
- файлы и секреты 2FA — AES‑256‑GCM; случайный 96-битный nonce для каждой операции;
- контрольная сумма открытого файла — SHA‑256, проверяется перед выдачей;
- TOTP-2FA по RFC 6238;
- случайные 256-битные публичные токены; в БД хранится только SHA‑256 токена;
- срок действия, пароль, лимит скачиваний и ручной отзыв ссылок;
- серверные сессии, HttpOnly/SameSite cookie, смена session ID при входе и CSRF-токены;
- RBAC и проверка доступа на каждом серверном запросе;
- CSP, запрет iframe, `nosniff`, политика разрешений и выдача файлов только как attachment;
- ограничение попыток входа и аудит значимых событий.

Это **серверное шифрование данных в хранилище**, а не end-to-end encryption: после проверки сессии и прав backend расшифровывает файл для скачивания. Полная модель и честные ограничения описаны в [docs/SECURITY.md](docs/SECURITY.md).

## Как показать преподавателю за 8–10 минут

1. Откройте главную: покажите стеклянное облако, параллакс, плавные появления блоков и student-first позиционирование.
2. Войдите как `demo@skyshelf.local`. В личных файлах загрузите TXT/PDF и добавьте его в избранное.
3. Откройте «Версии», добавьте новую редакцию с комментарием и восстановите первую версию.
4. Откройте «Учебные проекты» → «SkyShelf · СПО». Покажите кастомную обложку, дедлайн, команду и чек‑лист.
5. Отметьте файл итоговым, создайте ссылку преподавателю и откройте её в приватном окне.
6. Создайте отдельную ссылку на файл с паролем и лимитом одного скачивания. После скачивания ссылка станет недоступна.
7. Войдите как `reader@skyshelf.local`: интерфейс и backend запрещают изменение проекта.
8. Покажите «Безопасность» и «Журнал действий». Объясните AES‑256‑GCM, SHA‑256, Argon2id, TOTP и хеширование токенов.
9. Войдите как администратор. Покажите агрегаты и тарифы; отдельно подчеркните, что ADMIN не читает чужие файлы без членства.

## Стек и архитектурный подход

| Слой | Технология |
| --- | --- |
| Frontend | HTML, CSS, JavaScript без фреймворка; Atyp Display + SF Pro Display |
| Backend | Java 17, Spring Boot 3.5.16, REST API |
| Безопасность | Spring Security, Argon2id, AES‑256‑GCM, SHA‑256, TOTP |
| Данные | Spring Data JPA |
| Локальный показ | H2 file database + закрытое объектное хранилище |
| Docker/cloud-профиль | PostgreSQL 17 + MinIO + Nginx |

Backend — модульный монолит: auth, storage, projects, security/audit и admin находятся в одном приложении, но разделены контроллерами и сервисами. Frontend и backend независимы; небольшой Java-сервер разработки отдаёт статику и проксирует `/api`. Подробности и схемы: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Структура

- `frontend/` — страницы, дизайн, анимации, локальные шрифты и Java reverse proxy;
- `frontend/design-system.html` — визуальный инвентарь для переноса в Figma;
- `backend/src/main/java/ru/skyshelf/` — сущности, репозитории, сервисы и REST-контроллеры;
- `backend/src/test/` — интеграционные тесты;
- `backend/target/skyshelf.jar` — готовая исполняемая сборка;
- `tests/http-smoke.cjs` — сквозная проверка Final 1.0;
- `tests/browser-smoke.cjs` — сценарий настоящего браузера для локального компьютера;
- `docs/` — API, архитектура, безопасность, тестирование, Figma и материалы контрольной точки.

## Разработка

Для изменения Java-кода нужны Maven 3.9+ и JDK 17+:

```powershell
cd backend
mvn clean package
java -jar target/skyshelf.jar --app.demo=true
```

Во втором терминале из корня:

```powershell
java frontend/FrontendServer.java frontend 5500
```

После изменения `frontend/index.html`, `style.css` или `app.js` достаточно обновить страницу. `start.bat` запускает уже собранный JAR и сам исходники backend не компилирует.

## Docker: PostgreSQL + MinIO

1. Скопируйте `.env.example` в `.env`.
2. Укажите длинные разные пароли для PostgreSQL и MinIO.
3. Создайте 32-байтный ключ шифрования:

```bash
openssl rand -base64 32
```

4. Вставьте результат в `SKYSHELF_MASTER_KEY` и выполните:

```powershell
docker compose up --build
```

Интерфейс будет доступен на `http://localhost:8088`. MinIO и PostgreSQL наружу не публикуются. Для публичного стенда нужны TLS, `APP_DEMO=false`, отдельные production-секреты и проверенное резервное копирование.

## Данные и резервная копия локального режима

Локальные данные находятся в `backend/data`: H2-база и папка `objects`. Они образуют одну согласованную копию; не копируйте их по отдельности во время работы сервера.

После остановки обоих процессов:

```powershell
New-Item -ItemType Directory -Force backups
Compress-Archive -Path backend/data -DestinationPath ("backups/skyshelf-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".zip")
```

Для восстановления распакуйте сохранённую папку как `backend/data`, запустите сервис и скачайте несколько контрольных файлов. Не удаляйте предыдущую копию до проверки.
